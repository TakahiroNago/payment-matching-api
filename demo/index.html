payment-matching-api のブラウザ内デモ

入金消込デモ

請求と入金を入力すると、振込名義がどう正規化され、どの規則で、どの請求に消し込まれるか（または、なぜ人の確認待ちになるか）が出ます。 入力を変えると、その場で判定し直します。

判定はサーバーと同じ Rust のコードを WebAssembly にしたもので、このページの中だけで動きます。入力した内容はどこにも送信されません。データはすべて架空です。

取引先

カナ名が最初の名義になります。支店名つきなど、カナ名と違う名義で振り込まれる場合は別名に入れます（複数は「、」か改行で区切る）。

未消込の請求

入金（銀行明細の順）

名義の正規化

半角カナを全角にし、法人格（ｶ)、カブシキガイシャ など）と空白を除き、小書きの仮名を大きくして照合します。照合は完全一致だけです。

規則

上から順に評価し、最初に成立したものを採用します。自動確定するのは、説明が 1 通りに決まるときだけです。

規則条件説明が 1 通り複数
R1 単一一致名義から取引先を特定でき、同額の未消込請求がある自動確定最も古い請求を候補に
R2 合算一致取引先を特定でき、未消込請求 2 件以上の合計が入金額に一致する自動確定古い請求を優先した組み合わせを候補に
R3 手数料差引手数料を差し引いて支払う取引先で、R1・R2 が「入金額 + 手数料」で成立する候補候補
R4 金額のみ取引先を特定できず、同額の未消込請求がある候補候補

このデモにないもの

ここで動くのは、1 回の取り込みの自動判定だけです。データベースを通る部分（同じ明細の二重取り込みの防止、同時に確定したときの排他、候補の確定・却下・手動消込、取消の履歴、再判定）は含みません。 それらは API サーバーにあり、README とテストで説明しています。
